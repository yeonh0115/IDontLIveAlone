# 적용 안내

Android·Render 서버·Pi A·Pi B 센서 기록·PC 리포트를 함께 관리합니다. 장치는 Render HTTPS/WSS(443)로 연결하고 Aiven MySQL은 서버만 사용합니다. 학교망에서 DB 포트에 직접 접근할 필요가 없습니다. 실제 Wi-Fi의 HTTPS 허용 여부는 장치에서 확인합니다.

Annotated tag를 GitHub에 보관하며 후속 수정은 별도 커밋으로 기록합니다. Git에는 DB 내용, 얼굴 모델·샘플, SD 이미지, 인증키를 넣지 않습니다. 태그만 되돌려도 운영 데이터가 복원되는 것은 아닙니다.

2026-09-16 실제 Pi A의 SD 전체 15,931,539,456바이트와 부트 파티션을 PC의 비공개 체크포인트에 보관했습니다. 기존 Render 사진 478개도 원본과 PC 백업의 해시가 일치했습니다. 사용자 요청에 따라 이벤트 사진 보관을 끄며 유료 디스크 추가와 기존 사진의 새 서버 이관은 하지 않습니다. DB 백업 및 실제 배포 결과는 [VALIDATION.md](VALIDATION.md)에 기록합니다.

## 연결 방식

1. 새 앱으로 로그인합니다. 세션은 Android Keystore로 보호하며 로그아웃 시 해제합니다.
2. Pi A·Pi B·PC 프로그램은 장치 인증정보를 로컬에 생성합니다. 인증키는 앱에 입력하거나 공개하지 않습니다.
3. 장치가 표시한 8자리 코드를 앱의 **마이페이지 → 기기 연결**에 입력하고 역할·이름을 확인해 연결합니다. 코드는 10분간 유효합니다.
4. 서버가 로그인 계정과 장치를 연결하므로 Pi IP나 숫자 사용자 번호를 입력하지 않아도 됩니다. 카메라 영상과 새 장치 API는 연결 계정으로 구분합니다.

한 계정에는 CAMERA·SENSOR·REPORT 역할을 하나씩 연결합니다. 교체 시 기존 장치를 해제합니다. 신규 설치는 연결 코드를 사용하며 이전 환경변수 방식은 호환용으로 유지합니다.

## 사진 비저장 설정

기본 `EVENT_PHOTOS_ENABLED=false`에서 센서 이벤트는 로그·리포트 집계에만 기록합니다. 사진 촬영 예약과 업로드를 끄고 앱 응답의 사진 URL을 비웁니다. 실시간 영상과 로컬 얼굴 인식은 유지합니다.

얼굴 등록에 필요한 사진 3장은 임시로 전달해 Pi에서 학습하고 서버의 임시 파일은 작업 종료 후 정리합니다. 장치의 기존 학습 모델·등록 샘플은 인증 기능을 위해 유지합니다. 임시 서버 파일은 재배포 시 사라질 수 있으므로 진행 중인 얼굴 등록을 마친 뒤 배포합니다.

## 서버 설정

| 환경변수 | 설정 |
| --- | --- |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | 기존 Aiven 연결값 유지. 비밀번호는 Render 비밀 환경변수 |
| `PUBLIC_BASE_URL` | 기본 `https://idontlivealone.onrender.com` |
| `EVENT_PHOTOS_ENABLED` | `false` |
| `STORAGE_DIR` | 등록 처리 중 임시 파일 경로. 기본 `./data` |

연결 코드 방식에는 수동 `USER_NO`, `DEVICE_API_TOKEN`, `REPORT_API_TOKEN` 설정이 필요하지 않습니다. `/healthz`는 DB 연결을 포함해 검사합니다. JPA는 작업·세션·장치·중복 처리 방지 테이블을 추가하고 `daily_reports.photo_url`을 TEXT로 확장합니다. 기존 업무 테이블을 삭제하지 않으며 운영 DB 백업 후 적용합니다.

## SD 설치와 적용 순서

[SD_BOOTSTRAP.md](../deployment/SD_BOOTSTRAP.md)의 검증된 설치기를 사용합니다. 전체 SD 백업 후 부트 파티션에 설치 묶음을 준비하고 첫 부팅에 기존 계정·Python 환경으로 적용합니다. Wi-Fi·계정·모델을 보존합니다.

실제 카드의 작업 디렉터리·Python 경로를 확인해 지정합니다. 이번 카드에는 GPIO 24, 인식 기준 80, 연속 성공 2회, 출력 3초를 유지합니다. 저장소의 일반 기본값 23·85·4를 그대로 적용하지 않습니다. 설치기는 원래 코드·모델·설정·서비스를 Pi 내부에도 백업하고 다음 부팅부터 카메라·얼굴 인식 서비스를 실행합니다.

1. 진행 중인 얼굴 등록을 마치고 구 Pi 작업자를 중지합니다.
2. 코드 체크포인트·SD 이미지·DB 백업을 확보하고 테스트를 통과시킵니다.
3. 새 Render 서버를 배포하고 `/healthz`·인증·연결 코드 API를 확인합니다.
4. 새 Android APK를 설치하고 실제 계정으로 로그인합니다.
5. SD 설치 묶음을 준비하고 안전하게 꺼냅니다. Pi 부팅 후 앱에서 연결 코드를 등록합니다.
6. 영상·기존 얼굴 인식·등록 완료 표시·실제 GPIO 동작을 확인합니다. Pi B·PC는 각각 새 프로그램으로 교체하고 SENSOR·REPORT 역할로 연결합니다.

새 Pi를 구 서버에 먼저 연결하지 않습니다. 구 작업자는 새 임대·인증 계약을 지원하지 않으므로 서버·Pi·앱을 함께 교체합니다. 구 Pi B·PC의 DB 직접 쓰기 프로세스도 중지해야 합니다.

## 남은 범위

새 장치·세션·영상 API 및 얼굴 작업에 소유자 검사를 추가했습니다. 기존 비밀번호 저장 방식과 일부 레거시 API는 별도 보완 대상입니다. 얼굴 위조 방지·현장 인식률, Pi B의 다른 키패드·음성 프로그램, 외부 YOLO와 푸시 알림은 이번 범위에 포함하지 않습니다.
