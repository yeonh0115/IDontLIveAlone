# RTC 조회 및 카메라 복구 개선 · 2026-09-17

이번 변경은 중복 DB 조회, 연결 사이의 대기, 카메라 출력 정지와 앱 디코딩 정지 감지에 한정한다. 기존 로그인·권한 정책, 비밀번호 저장 방식, LAN 바인딩, GPIO와 얼굴 모델은 변경하지 않는다.

## 서버

실제 HTTP 요청과 Hibernate 통계로 측정한 SQL SELECT 수다. 로컬 H2에서 쿼리 횟수를 검증한 것이며, 운영망의 응답 시간이나 영상 프레임 지연을 같은 비율로 보장하는 수치는 아니다.

| 요청 | 이전 | 이후 |
|---|---:|---:|
| 앱 연결 생성 | 5 | 3 |
| 앱 연결 상태 조회 | 6 | 4 |
| Pi 대기 offer 조회 | 6 | 4 |
| Pi answer 제출 / 연결 상태 조회 | 6 | 4 |
| 연결 완료 뒤 Pi의 새 offer 확인 | 6 | 2 |
| 활성 연결 없는 Pi 조회 | 2 | 2 |
| 앱 연결 종료 | 2 | 2 |

같은 요청에서 확인한 호출자의 정보를 재사용한다. DB 읽기는 전역 상태 잠금 밖에서 실행하고, 돌아온 뒤 현재 세션을 다시 확인한다. DB 응답을 기다리는 사이에 종료·교체·만료·삭제된 연결을 되살리지 않는다. 같은 answer의 중복 제출과 서로 다른 answer의 경합도 검증한다. 오래된 장치 확인 요청은 새 소유자의 연결을 종료하지 않는다.

반복 SQL 출력은 기본적으로 끄고 `SHOW_SQL=true`, `FORMAT_SQL=true`로 필요할 때만 켠다. SDP와 영상 데이터를 DB에 저장하지 않는 기존 구조를 유지한다.

UTC 환경의 서버 `clean build`에서 전체 93개 검사가 통과했다(실패·오류·건너뜀 0). 실제 SQL 횟수 검사와 느린 DB, 동시 종료·교체·만료·삭제·answer 및 오래된 장치 요청 경합 회귀 검사를 포함한다.

## Pi와 Android

- Pi가 완성 JPEG를 10초 동안 받지 못하면 rpicam 자식 프로세스를 종료·회수한 뒤 재시작한다. 데이터가 준비되면 즉시 읽으므로 정상 촬영에 고정 대기를 추가하지 않는다. 기존 최신 프레임 전달 방식, 640×480 촬영 및 프레임률을 유지한다.
- Android 1.2.3/code6은 수신 바이트가 늘어도 실제 디코딩 프레임이 멈추면 정지를 감지한다. 서버 기동·연결 준비 시간을 영상 정지로 오인하지 않도록 연결 후부터 감시한다. 기존 재시도 버튼을 사용하며 자동 무한 재접속은 추가하지 않는다.
- Pi 66개 검사(새 카메라 회귀 10개 포함), Android JVM32개 및 JavaScript16개, 배포 도구13개 검사를 통과했다. 실제 Pi 드라이버 고장 유도 시험은 포함하지 않는다.
