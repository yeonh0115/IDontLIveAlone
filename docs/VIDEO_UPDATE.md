# 영상 화질·지연 개선 (앱 1.1)

기존 영상은 320×240, JPEG 품질 40이며, 사용자가 확인한 지연은 약 1~3초였습니다. 이번 변경은 촬영 기본값을 **640×480, JPEG 품질 70**으로 올리고 양쪽 전송에 쌓일 수 있는 오래된 화면을 제한합니다. 실제 학교 Wi-Fi에서의 촬영→휴대폰 지연과 체감 화질은 업데이트 후 측정해야 합니다.

## 변경 내용

- Pi는 최대 15fps로 촬영합니다. 클라우드에는 최대 10fps로, 한 프레임을 보낸 뒤 서버의 수신 확인을 받아야 다음 최신 프레임을 보냅니다. 2초 안에 송수신이 끝나지 않으면 그 연결을 버리고 재연결합니다.
- 앱은 WebView 대신 ImageView를 사용합니다. `/ws/viewer` 연결에서 `next`를 보내 최신 JPEG 한 장을 받고 표시한 뒤 다음 장면을 요청합니다. 동시 요청·디코드·표시 대기를 제한하며 화면을 벗어나면 연결을 종료합니다.
- 표시할 새 장면이 없으면 서버는 `waiting`을 반환합니다. 중복 프레임과 서버 수신 후 1초가 지난 프레임은 새 영상으로 보내지 않습니다. 앱은 오래 멈춘 화면을 연결 대기 표시로 바꿉니다.
- 영상의 원래 비율을 유지합니다. 얼굴 인식 입력 크기는 기존 수준으로 제한하고 기존 얼굴 모델·기준값·GPIO 설정을 유지합니다.
- 사진 저장은 계속 꺼져 있습니다. 영상은 메모리에만 둡니다. 유료 서비스나 새 DB 연결 방식은 추가하지 않습니다.

단일 프레임을 확인하며 전송하므로 실제 FPS는 네트워크 왕복 시간에 따라 달라집니다. 최대 10fps 설정이 항상 10fps를 보장하는 것은 아닙니다. 서버 수신 시각이나 ACK 시간만으로 전체 지연을 측정할 수 없으므로 카메라 앞 손 움직임 또는 시계로 실제 앱 화면과 비교합니다.

## 전송량과 무료 운영

원본 서버(`0430fd3`)는 새 장면인지 확인하지 않고 10ms마다 같은 JPEG를 반복 전송했습니다. 현재 운영 서버(`0b5789a`)에는 중복 방지 처리가 있습니다. 기존 앱은 영상 WebView 연결의 화면 종료 처리가 빠져 있었으며, 이번 앱에서 이를 명시적으로 종료합니다. 과거 청구량 중 각 원인이 차지한 비율은 과거 실제 접속 시간·프레임 크기 기록 없이 확정할 수 없습니다.

새 영상도 JPEG를 중계하므로 서버 출력 트래픽은 계속 발생합니다. 특히 해상도·JPEG 품질 상승은 한 장의 크기를 키울 수 있습니다. 예를 들어 20KiB × 10fps는 헤더를 제외하고 약 0.737GB/시간입니다. 무료 요금제 선택만으로 무제한 영상 시청이 무료가 되는 것은 아니며, 이 버전에는 월별 데이터 사용량 차단 기능이 없습니다. [Render 출력 대역폭 정책](https://render.com/docs/outbound-bandwidth)을 별도로 확인합니다.

## 적용 순서

1. 검증된 서버를 먼저 배포합니다. 기존 Pi와 앱의 영상 경로도 유지하여 새 코드 적용 전까지 사용할 수 있습니다.
2. 기존 앱을 삭제하지 않고 새 `IDontLiveAlone-1.1.apk`를 업데이트 설치합니다. 기존 로그인과 CAMERA 연결을 유지합니다.
3. Pi 터미널에서 다음 한 줄을 실행합니다. 다운로드와 파일 검증이 끝나기 전에는 서비스를 정지하지 않습니다.

```sh
f=$(mktemp) && wget -qO "$f" https://raw.githubusercontent.com/yeonh0115/IDontLIveAlone/video-v1.1/deployment/update_camera.py && sudo python3 "$f" --apply
```

`LOCAL CAMERA OK`는 새 로컬 영상과 서비스 실행 상태를 확인한 결과입니다. `CLOUD VIDEO OK`는 이번 시작 이후 새 ACK 방식의 서버 연결을 확인한 결과입니다. 얼굴 식별과 실제 문 동작을 검증한 메시지는 아닙니다. 마지막 줄이 `UPDATE STOPPED`이면 그 줄만 공유하고 무리하게 재설치하지 않습니다.

업데이트기는 고정된 Git 커밋의 소스 세 파일을 SHA256으로 검증합니다. 기존 소스와 환경파일은 Pi의 `/var/backups/idontlivealone/video-update-*`에 비공개 백업합니다. 로컬 카메라 시작 실패 시 소스를 자동 복원합니다. 네트워크 장애로 클라우드 연결 확인만 실패한 경우에는 정상 실행 중인 로컬 카메라를 유지하고 미확인 상태를 알려줍니다. 갑작스러운 전원 차단까지 자동 복구를 보장하는 전체 OS 트랜잭션은 아니므로 업데이트 중 전원을 유지합니다.

## 현장 확인

앱 홈 화면에서 손을 움직여 지연과 화질을 비교합니다. 다른 탭에 갔다가 돌아오기, 앱을 배경에 뒀다가 복귀하기, Pi 재부팅 후 자동 영상 재연결도 확인합니다. 얼굴 등록·기존 얼굴 인식·문 제어는 별도 확인합니다.

관련 공식 문서: [Raspberry Pi 카메라 옵션](https://www.raspberrypi.com/documentation/computers/camera_software.html), [Render WebSocket 지원](https://render.com/docs/websocket).
